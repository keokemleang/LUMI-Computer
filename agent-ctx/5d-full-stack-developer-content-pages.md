## Key decisions
- Server components by default; `'use client'` only for filters/views (DownloadsView, BlogView), Markdown renderer (needs `react-markdown`), NewsletterSignup, and ContactForm.
- Reused the avatar-color + initials pattern from `courses/[slug]/page.tsx` (semantic palette, deterministic hash) for blog author bio + sidebar, community contributors, and about team — kept helpers inline per page (foundation `data.ts` not modified).
- Pass only serializable subsets across the server→client boundary: `DownloadLite` (no `Date`), `BlogLite` (ISO-string `createdAt`), and a `Pick<ProjectParsed, ...>` for the community showcase (matches `ProjectCard` props).
- All colors are semantic tokens only — `bg-primary/10 text-primary`, `bg-success/15 text-success`, `bg-warning/15 text-warning`, `bg-danger/15 text-danger`, `bg-info/15 text-info`, `bg-muted`, `text-muted-foreground`. No indigo/purple, no hardcoded hex.
- Download button is a plain `<a target="_blank" rel="noreferrer" download>` per task spec — no increment API.
- Blog markdown uses `react-markdown` with explicit component overrides (no `@tailwindcss/typography` plugin).
- Breadcrumbs use the shadcn `<Breadcrumb>` family; prev/next links use `ChevronLeft/ChevronRight` from lucide-react.
- All images use `next/image` with `alt` and proper `sizes`; blog post cover uses `priority`.
- Map placeholder is a CSS-grid-pattern div (no external map embed) using `var(--border)` for the grid lines.
